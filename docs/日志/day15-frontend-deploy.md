## 二、今天必须先解决的一个坑（我已改好）

### 问题：Day 13 用了路由，静态托管会让 `/tasks` 变404

Day 13 引入了 `react-router-dom`，页面地址变成 `/`、`/tasks`、`/tasks/:id`。
**前端路由的特点**：刷新或直接访问 `/tasks` 时，浏览器会真的去请求
域名下的 `/tasks` 这个**文件**，而不是交给前端路由处理。

静态托管默认**没有「History 回退到 index.html」的机制**，我本地实测确认：

| 请求 | 结果 |
| --- | --- |
| `/` | 200 ✅ |
| `/assets/index-xxx.js` | 200 ✅ |
| `/tasks` | **404** ❌ |
| `/tasks/sample-01` | **404** ❌ |

**后果**：页面能打开，但**一刷新就白屏**，而且课程第 1284 行要求
「把前端公网链接发给同伴，请对方打开确认」—— 同伴一点导航没问题，
一刷新就白屏。

### 已做的改动：`app/vite.config.ts` 加 `base: './'`

官方《部署指南》第五节明确要求：

> **在项目配置中将公共路径设置为相对路径 `./`，避免静态资源加载失败。**
> —— https://docs.cloudbase.net/hosting/web-hosting-guide

实测对比：

| | `index.html` 里的资源引用 | 挂到子路径时 |
| --- | --- | --- |
| 不设 `base` | `<script src="/assets/index-xxx.js">` | 去找 `/assets/` → **404 白屏** |
| 设 `base: './'` | `<script src="./assets/index-xxx.js">` | 找 `/priorknow/assets/` → **正常** |

**本地开发已验证不受影响**（dev 模式走 `/@vite/client`、`/src/main.tsx`，资源 200）。

⚠️ **但这只解决了「资源 404」，没解决「路由 404」** —— 见第五节。

## 三、部署：云端构建走不通，改用本地构建 + 直接上传

### 🔴 云端构建两次都失败（第二次命令已改对仍失败）

| 次序 | BuildCmd | 结果 |
| --- | --- | --- |
| 第一次 | `tsc --noEmit && vite build`（裸命令） | × 构建失败 |
| 第二次 | `npm run build`（**已改对**） | × **仍然失败** |

⚠️ **第二次失败说明「命令问题」不是全部原因**，但云端构建日志拿不到
（`tcb` 没有取日志的命令；试了 6 个 `tcb api` action 都不行）。

**我把两个假设逐一证伪了**：

| 假设 | 怎么验的 | 结果 |
| --- | --- | --- |
| 是不是裸命令找不到 `tsc` | 干净环境跑 `tsc --noEmit && vite build` | ❌ **证伪**（裸命令确实失败，但改成 `npm run build` 仍失败说明还有别的原因） |
| 是不是 Node 版本不满足 | 装了 **Node 20.20.2**（vite 8.3 要求 `^20.19.0 \|\| >=22.12.0`），干净环境跑完整流程 | ❌ **证伪**（`npm install` ✅ 28 包、`npm run build` ✅ `built in 719ms`） |

→ 代码没问题、依赖没问题、Node 版本也没问题。
**剩下的差异只能在云端构建环境本身，而它不给日志。**

### ✅ 改用的方案：本地构建 + `tcb hosting deploy`

```bash
# 1. 本地构建（已验证：Node 20 与 Node 22 下都成功）
cd D://Custom_Programs//MYAPP//PriorKnow//app
npm run build

# 2. 直接上传产物到静态托管根路径
tcb hosting deploy ./app/dist / -e priorknow-d0go4uh2uc0f62465
```

实测结果：

```
Total files: 3
√ Successfully uploaded 3 file(s)
│   √    │ /assets/index-D3F369g8.css │
│   √    │ /assets/index-c5G0qL7y.js  │
│   √    │        /index.html         │
```

⚠️ **不要加 `--safe`**：实测它会在上传成功后报
`一致性校验失败：missing=/index.html,...` 并**自动回滚**，
但远端其实已确认是空的——`--safe` 的校验与上传不同步。**去掉它就正常了。**

### 🔴⚠️ 控制台会一直显示「失败」，那是**云构建记录，不是线上状态**

在控制台「应用详情 → priorknow-app → 部署详情」里，你会看到
`priorknow-app-002 状态：失败`（开始时间 2026-10-06 16:16:29）。
**那不要管、也不用去重试** —— 线上是好的。

**为什么会这样**：那是 `tcb app deploy`（云端构建流水线）的历史记录。
我后来改用 `tcb hosting deploy`（本地构建 + 直传），**根本没走那条流水线**，
所以这条记录**永远不会变绿**。

**判断「线上有没有东西」要看这两处，别看控制台那个状态**：

```bash
# ① 静态托管里到底有哪些文件（最权威）
tcb hosting list / -e <envId>
#   应看到 index.html、assets/index-xxx.js、assets/index-xxx.css

# ② 直接访问公网地址
curl -o /dev/null -w "%{http_code}" https://<默认域名>/
#   应返回 200
```

本项目实测（2026-10-06 17:49）：
```
assets/index-D3F369g8.css   2026-10-06 17:49:14   16.69 KB
assets/index-c5G0qL7y.js    2026-10-06 17:49:14  383.43 KB
         index.html         2026-10-06 17:49:15    0.50 KB
```

⚠️ **一个容易误判的坑**：失败的应用也有自己的域名
（`priorknow-app-priorknow-...webapps.tcloudbase.com`），
**访问它会返回 200、还像是正常页面** —— 但那是 **CDN 缓存**，
不是它自己的产物（`tcb app versions detail` 里 `VersionDomain` 为空、
`Artifacts` 为 `[]` 就说明它从未产出任何东西）。
**别拿这个当「它部署成功了」的证据。**

## 五、⚠️ 已知限制：`/tasks` 刷新会 404（今天不做修）

**实测结论**：静态托管**没有** History 回退机制，官方文档全篇也没给这个配置项。
所以 `/tasks`、`/tasks/sample-01` **直接访问或刷新会 404**。

**今天的验收不受影响**，因为：
- 课程第 1283 行只要求「浏览器打开公网页面地址，确认页面能打开」
- 同伴打开链接看到的是 `/`（根路径），点导航是**前端路由跳转，不发请求**，能正常切

⚠️ **但 Day 20 前得解决**。可选方案（都还没验证，需到时候查证）：

| 方案 | 代价 |
| --- | --- |
| 改用 `HashRouter`（`#/tasks`） | 最小改动，但地址带 `#`，不优雅 |
| 建 `tasks.html` 等副本，让每个路径都有对应文件 | 产物变多，且 `/tasks/sample-01` 这种动态路径解决不了 |
| CloudBase 侧开启某个路由回退开关 | **不确定是否存在** —— 官方文档没查到，需在控制台找 |

已登记进待办，**不塞进今天** —— 课程第 1208 行「今日不做」之外的额外改动。
