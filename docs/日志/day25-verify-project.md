## 一、检查项从哪来（不是通用模板）

课程要求「检查项必须来自本项目真实踩过的坑」。逐条对着 Day 15–24 的日志翻了一遍：

| 曾经的坑 | 出在哪天 | 固化成哪一项 |
| --- | --- | --- |
| 请求打到静态托管而不是云函数（`text/html` + `NoSuchKey`） | Day 15 | **B1** |
| 静态托管只认本地构建直传；判生效不能看 list 时间戳、也不能看 `*.webapps` 的 200（CDN 缓存） | Day 20 | **B2** |
| 云函数路由前缀（`gatewayPath: "/api"` 是前缀匹配） | Day 15 | **B3** |
| CloudBase 网关按**安全域名名单**放行，名单外仍回 204 但**没有** `allow-origin` 头 | Day 21 | **B4** |
| `app.rdb()` 失败**不抛异常**，`ok:true` + `items:[]` 与「读不出」必须分开 | Day 17 | **B5** |
| `seq` 靠 `BEFORE UPDATE` 触发器推进；漏了它，改过的任务别的设备永远拉不到且不报错 | Day 16 / 22 | **B6** |
| `PATCH` 的 `select` 漏 `seq` → `cursor: null`（那个线上真 Bug） | Day 22 | **B6** |
| `daily_budget` 是第二张表，建表脚本刻意没并进 `schema.sql` | 追加需求 | **B7** |
| `.gitignore` 只挡将来的提交，进过历史就得换 key | Day 23 | **A4** |
| 凭证走运行角色，代码里不该有任何 secretId / secretKey | Day 23 | **A3** |
| 开发开关与「Day N」文案漏进构建包 = 当着评委自报作业 | Day 24 | **A2** |
| 类型错不会让 dev 起不来，只在出包时炸（`TS6133`） | Day 24 | **A1** |

**没有对应的坑的检查项，一条都没加。** 加通用模板（「有没有 README」「commit 规范不规范」）会让这份清单变长而没有分量。

## 三、第一次跑完全绿 —— 然后找出 4 处「太松」

全绿最容易骗自己。于是把每一项问一遍：**「如果它坏了，这一项真的会红吗？」** 改掉的四处：

| # | 原来怎么写 | 为什么是漏报 | 改法 |
| --- | --- | --- | --- |
| 1 | A2 只扫 `dist/assets/*.js` | `index.html` 的 `<title>`、注释、CSS 伪元素都不在扫描范围内 | 扫 JS + CSS + `index.html` → **当场揪出真问题**：`index.html` 里有一条注释写着「Day 24 收尾：站点图标」 |
| 2 | A3 只扫源码 | `VITE_` 前缀的环境变量在**构建时内联进 bundle** —— 只扫源码会漏掉「打包之后才出现」的密钥 | 把 `app/dist` 一起扫 |
| 3 | B2 只比 `assets/index-*.js` 的 hash | 改 `index.html`（title / meta / 注释）**不会改 JS 的文件名**，于是「改完忘了部署」会被判 PASS | 连 `index.html` 正文一起比（去空白后逐字相等） |
| 4 | B5 只 `GET ?since=0` 读一次 | 空库也是 `{ok:true, items:[]}` —— 分不清「真空库」和「读不出来但壳是对的」 | 改成**读写闭环**：写一条 → 拉回来比对标题 → 删掉 |

**第 1 条和第 3 条抓到的是真东西，不是假想**：
把 A2 放宽后立刻红了一条 —— `app/index.html` 里那句注释会原样进构建产物。
处理方式不是把判据改回去让它变绿（那是改断言不改代码），而是把注释里的「Day 24」去掉，
并在注释里留一句警告：「注释会原样进构建产物，别写 Day N」。

**第 3 条更值钱**：改完 `index.html` 后 B2 立刻变红 —— **因为改完忘了重新部署**。
一条自己写的检查，抓到了自己刚犯的错。

## 四、故意弄坏（今天真正要交的证据）

只跑全绿证明不了任何事。逐项弄坏 → 跑 → 确认对应项变红 → 还原：

| # | 弄坏了什么 | 期望红 | 实际结果 |
| --- | --- | --- | --- |
| 1 | 往 `app/src/core/types.ts` 追加一行 `const secretKey = "AKIDfakefakefake1234"` | A3 | ✅ `[A3] FAIL —— 2 处：AKID…@types.ts secretId/secretKey 字面量@types.ts`（同时 B2 红：改了源码没部署） |
| 2 | 把 `.env` 从 `.gitignore` 里删掉 | A4 | ✅ `[A4] FAIL —— .env **未被忽略**` |
| 3 | 往 `app/index.html` 注释里写「Day 25」 | A2 | ✅ `[A2] FAIL —— 1 处：Day 25@index.html` |
| 4 | 健康接口地址写错一段（只换地址，不动线上） | B3 | ✅ `[B3] FAIL —— 404 {"ok":false,"error":"没有这个接口"}` |
| 5 | OPTIONS 换成一个不在名单里的 Origin（手做） | B4 | ✅ 只有 `204`，**没有** `allow-origin` 行 —— 判据能分辨 |
| 6 | 拉取起点改成「跳过刚写的那条」（`since = postCursor`） | B5 | ❌ **仍然 PASS** —— 见下 |

### 第 6 条为什么没红（这次失败比成功有用）

改成 `since = postCursor`（正好等于本区最大 `seq`）之后，服务端返回了 **19 条**，
里面**包含**刚写的那条 —— 因为契约里有一条判据：

> **`since == 本区 max(seq)` 且 items 空 → 当成全量拉取，附一条 notice。**

于是「跳过刚写那条」这个动作被服务端的兜底救了回来，读回来的内容是对的，判定 PASS **是对的**。
要真正弄红 B5，得让**内容**不一致：把探针标题改成带首尾空格
（服务端 `trim` 后入库）→

```
[B5] FAIL  读接口能原样读回 —— GET since=449 → 1 条 · 读到了但内容不一致：写入「 读回探针 … 」/ 读回「读回探针 …」· DELETE 200
```

**结论**：B5 的判据是真的在比内容，不是只看「有没有报错」。也顺便确认了那条「全量兜底」判据在线上是活的。

> 顺带修了一处误报式表述：原来不论「没找到」还是「内容不一致」都只说「没读到刚写的那条」，
> 现在分开说 —— 证据必须能核对，含糊的话等于没有证据。

## 六、没做的（清单外只记录，不做）

1. **对接口身份认证** —— `X-User-Id` 客户端自报，知道地址就能读写任何人的分区。这是**已知缺口**，
   不是「检查能查出来的故障」，已写进 SKILL.md 的边界一节。
2. **自动化流水线**（挂 hook / CI / 部署前自动跑）—— 课程今天明确不做。
3. **默认域名中间页**（只对浏览器导航生效，`curl` 看不到）—— 只能人工过闸，写进了边界。
4. **把检查结果存成历史报告**（趋势对比）—— 现在的输出是给人看的，不是给机器读的。

## 八、怎么用

```bash
# 一条命令跑完 11 项
node skills/verify-project/verify.mjs

# 换成别的环境（回滚演练、新环境验证）
WEB_URL=https://… API_URL=https://…/api node skills/verify-project/verify.mjs
```

**判读只有三句话**：
1. 绿的不代表界面没问题 —— 它只证明「该通的地方通」。
2. 红的一定要看证据那一列（状态码 / 文件名 / 响应头 / 读回来的原文），**不看名字猜原因**。
3. 改完检查项，**先弄坏一次**再收工。

新对话里直接说「运行 verify-project」即可；工具读不到 `skills/` 时，
把 `SKILL.md` 全文贴进对话、说「按这份清单逐项检查」就行。
