## 零、一句话结论

**写操作失败时，界面把它当成「数据读不出来」处理** —— 于是用户的任务列表整块消失，
标题还说是「没读出来」，而实际是「没写进去」；同一句话里，标题和正文自相矛盾。

修复落在 `app/src/ui/useTaskQueue.ts`：把「写失败」从 `error`（那个整页开关）里解出来，
单独一个 `writeError`。**修的不是文案，是「用户还看不看得见自己的数据」。**

| | 修复前 | 修复后 |
| --- | --- | --- |
| 「全部任务」页点「恢复为待办」失败 | 整页换成「任务列表没读出来」，**2 行任务 → 0 行** | 列表原样留着，上方补一条写失败提示 |
| 那句说明 | 「**恢复**『待恢复的任务』失败：写入被…拦下了」 | 同左（这句本来就对，问题在它被放进了「读失败」的位置） |
| 「重试」按钮指向 | 重新读库 —— 而读库本来是好的 | 不再需要；用户可以换个动作再试 |

## 二、第二步：定位

### 2.1 复现步骤（照着做一定能重现）

前置：本机 `npm run dev`，浏览器打开 `http://localhost:5199/#/tasks`。

1. 在「数据与设置」里点「导入 JSON」，选一份**两件任务**的文件
   （一条 `status: "done"`、一条 `status: "todo"`）；
2. 把页面底部「数据层状态（开发用）」切到 **「模拟写入失败」**；
3. 在「全部任务」里，对那条已完成的点 **「恢复为待办」**。

> ⚠️ 第 2 步用的是项目自带的演示开关，不是造假：它拦在**写入**那一层，
> 读取照常。真实世界里等价的情形是「IndexedDB 配额满了」「云端删除请求失败」——
> 都同样只坏写、不坏读。

### 2.2 现象原文（修复前，一字未改）

页面标题：

```
任务列表没读出来
```

标题下面那句：

```
本机数据  恢复「待恢复的任务」失败：写入被「模拟写入失败」开关拦下了。把开关调回「正常」再试一次。
```

页面下方：

```
重试
```

**任务行数：2 → 0。**

同一场景点「删除」：同样 2 → 0，同样「任务列表没读出来」。

### 2.3 已尝试的动作（做完才敢下结论）

| 试了什么 | 结果 | 排除了什么 |
| --- | --- | --- |
| 切回「正常」再点一次 | 一切正常，任务还在 | 不是数据真的没了 —— **库是好的，是界面把它藏了** |
| 点那个「重试」 | 页面恢复，任务回来 | 重试指向的是**重新读库**，而读库本来就没坏 → 这个按钮治的是错的病 |
| 换成点「完成」（同样写失败） | 只有一条提示条，列表不动 | 说明**不是**「写失败必然导致整页错误」，而是某些按钮的处理方式不同 |
| 看控制台 | 只有 favicon 404 | 界面没抛异常 → 不是运行时崩溃，是**分支走错了** |

### 2.4 根因

`app/src/ui/useTaskQueue.ts` 的 `act()` —— 五个写按钮共用的外壳：

```ts
// 修复前
} catch (err) {
  setError(explainError(err, failureNote))   // ← 问题在这一行
  return false
}
```

而 `error` 在全站只有一个用途：**决定整页换成「读不出来」**。
三个页面（今日队列 / 全部任务 / 任务详情）开头都是同一句：

```ts
if (error !== null) { return <整页错误块 /> }
```

于是「这条没删掉」被翻译成了「你的数据读不出来」。
**`error` 这个变量的名字是「读失败」，但它被当成了「出错了」用。**

这件事项目里其实早就想清楚过一次 —— `useTaskQueue.ts` 里 `completeTask()` 的注释写着：

> 「写入失败不该把读得好好的队列也换掉。用户遇到的是『这一件没完成』，不是『队列看不见了』。」

但当时**只改了「完成」一个按钮**，理由没有被推广到其余五个。

### 2.5 顺手挖出来的同一个根因的第二个症状

同一份清单的第 3 关：导入一份**同一条任务写了两遍**的 JSON（编号撞了）。修复前界面上同时出现两句互相矛盾的话：

```
[输入问题] 导入未完成：文件内容有问题，你原来的数据没有被改动（具体是哪一条，见队列那一块的提示）。
```

```
未预料的问题  导入失败：出错了，原因不在前面几类里（tasks.bulkAdd(): 1 of 2 operations failed.
Errors: ConstraintError: Key already exists in the object store.）。刷新页面再试，反复出现就把这句话截图反馈。
```

三件事同时不对：

1. **同一件事两处说法不同**（一处「输入问题」，一处「未预料的问题」）；
2. **英文原文漏到了界面上** —— 这正是 Day 23 修掉的那类问题，从另一条路回来了；
3. 列表还是整块消失了（同一个根因）。

第 2 点的原因是 `explainError` 的存储错误表里少了 Dexie 批量写抛的 `BulkError`
（它撞主键时抛的**不是** `ConstraintError`，而是 `BulkError`，里面包着 `ConstraintError`）。

## 三、第三步：修复

原则只有一条：**读失败归 `error`（整页换掉），写失败归 `writeError`（原地补一条，列表不动）。**
判据是「用户还能不能继续看见并操作他原来的数据」。

| 文件 | 改动 |
| --- | --- |
| `app/src/ui/useTaskQueue.ts` | 新增 `writeError` / `dismissWriteError`；`act()` 的 catch 改成写 `writeError`，**不再碰 `error`**；`act()` 成功后清掉它。`error` 的注释改成「它现在只表示读不出来」 |
| `app/src/ui/WriteErrorBar.tsx` | **新增**。写失败那条提示的容器（`ErrorNote` + 「知道了」）。和 `ErrorNote` 分工：一个管「长什么样」，一个管「出现在哪儿、怎么收起来」 |
| `app/src/ui/TasksPage.tsx` | 渲染写失败提示，位置在提示语之后、列表之前 |
| `app/src/ui/TodayQueue.tsx` | 同上（删除失败在这里说） |
| `app/src/ui/TaskDetailPage.tsx` | 同上（删除 / 恢复 / 改标题失败在这里说） |
| `app/src/ui/DataPanel.tsx` | 导入失败那句从「文件内容有问题」改成「**原数据没有被改动，原因看页面上方**」。原来那句是**猜**的：真原因可能是编号撞了（输入），也可能是存储满了（本机）。猜错比不说更糟 —— 用户会去改文件，而该做的是导出备份清空间 |
| `app/src/ui/errors.ts` | `STORAGE_HINTS` 补 `BulkError` 一条人话 |
| `app/src/styles.css` | `.write-error` / `.write-error-close`（flex 一行，按钮「知道了」） |
| `app/src/App.tsx` | 页头 Day 标记 → Day 24 |

`DataPanel` 的 `Status` 判别联合加了第三支 `{ tone: 'bad'; text }`：
**不带标签的失败** —— 原因是别处报的，这里只补「原数据没动」。
硬贴标签反而会说错（这一层根本不知道是哪一类）。

### 为什么不做成「给 act 加一个开关」

试过那条路：`act(action, note, { keepPage: true })`。
它能让 5 个调用点一处不改就修好，但等于把「写失败要不要藏起整页」变成每个调用点自己选的事 ——
下次谁忘了传，Bug 就回来。所以选的是让**语义本身**分开：`error` 只能是读失败，写失败没有第二个去处。

## 六、课程那句「不要替 AI 下结论」

这条要求的意思是：**记录里只写看到的东西，不写「我觉得是 XX 问题」**。
本文 2.3 那张「已尝试动作」表就是照这个写的 ——
每一行都是「试了什么 / 看到什么 / 因此排除了什么」，没有一句是猜的。

其中「换成点『完成』也一样写失败，却只有提示条」这一行是关键：
它把结论从「写失败都会导致整页错误」推到了「**有些按钮的处理方式不一样**」，
根因才落到 `act()` 上，而不是落到「错误提示组件坏了」。

### 9.3 两个当场踩到的坑（值得记）

🔴 **红色是行动色，不是背景色。**
第一版给 `.card h2` 用了强调红左边框，截完图发现**四张卡四条红** ——
和「7 个红序号」是同一个错误：把一个只能标「当前该点的那个」的颜色，
当成了装饰。判据很简单：**同一屏里 `--accent` 出现几次？超过「当前导航 + 主按钮 + 队首」就该收。**
现在全屏只有三处红。

🔴 **等宽字体不能用在混中文的行。**
`.queue-meta` 里混着「已逾期或 7 天内到期」，等宽会把中文字距也拉成等宽，
读起来像代码注释。数字对齐交给 `font-variant-numeric: tabular-nums`，
字体换回正文同款 —— 这两件事本来就该分开管。

⚠️ 顺带暴露一个项目配置缺口：`import.meta.env.DEV` 第一次用时 `tsc --noEmit` 直接报
`Property 'env' does not exist on type 'ImportMeta'`。项目当初手写 tsconfig，
**缺 `src/vite-env.d.ts`**。补上 `/// <reference types="vite/client" />` 才过。
