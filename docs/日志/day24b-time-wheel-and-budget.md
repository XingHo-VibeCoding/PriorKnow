## 一、时间选择：从原生下拉改成滚轮时钟

### 1.1 原来的样子

`<input type="datetime-local">` —— 日期和时间绑在一个控件里。
用户的原话是「日期还行，时间滚轮选取……而不是一个生硬的下拉菜单」。
日期那半他认可，问题在时间：原生时间控件长什么样由浏览器决定，
点开就是一个一格格跳的列表，和这套界面的气质对不上。

### 1.2 现在的样子

拆成两个控件：

```
截止时间
[ 2026/11/05 📅 ]  [22] : [30]     ← 触发按钮本身就是个小数字时钟
                   ┌──────────────┐
                   │  20     28   │   ← 渐变淡出
                   │  21     29   │
                   │ [22] : [30]  │   ← 选中框（不随滚动移动）
                   │  23     31   │
                   │  24     32   │   ← 渐变淡出
                   │ 22:30 截止 完成│
                   └──────────────┘
```

四件事凑出「数字时钟」的感觉：

| 做法 | 实现 |
| --- | --- |
| **带框** | 两位数字各一个 `1px` 边框的圆角小格；滚轮里再用一个固定位置的框圈住正中间那格 |
| **冒号** | 触发按钮和面板里都是两列中间一个 `:`，整体读起来是 `22:30` |
| **边缘渐隐** | 滚动容器加 `mask-image: linear-gradient(...)`，上下 30% 淡出 |
| **滚动吸附** | `scroll-snap-type: y mandatory` + 每格 `scroll-snap-align: center`，松手必停整格 |

### 1.3 🔴 三个数字必须互相咬死

```
格子高 36px（TimePicker.tsx 的 ITEM_H）
可见 5 格 → 容器高 180px（styles.css 的 .wheel-box）
上下各留 2 格 → 72px 空白（.wheel-spacer）
```

**少任何一处都会坏**，而且坏得很隐蔽：

- 没有那 72px 空白 → `00 时` 永远停在最上面那一格，**滚不到正中间，等于选不中**；
- 格子高与 `ITEM_H` 不一致 → `scrollTop = 值 × 36` 会越滚越偏，到 23 时能偏出一整格；
- 选中框的 `top` 没跟着改 → 框圈住的是错的数。

所以这三处在代码里都写了交叉引用注释。**改一个就要改另两个。**

### 1.4 为什么用原生滚动，不自己写拖拽

浏览器的 `overflow-y: auto` 已经带了惯性、触摸板双指、滚轮、滚动条、
`overscroll-behavior`、无障碍焦点——自己写一套 `pointermove` 等于把这些全部重做，
而且触摸屏上多半更差。我们只做两件浏览器不替我们做的事：

1. **把滚动位置吸附到整格**（`scroll-snap`）；
2. **把外面的值写回滚轮位置**（`useEffect` 里设 `scrollTop`）。

⚠️ 第 2 件有个坑：如果每次值一变就设 `scrollTop`，用户正滚到半格时会被**拽回整数格**，
手感变成一卡一卡。所以用一个 `fromScroll` ref 标记「这次变化是用户滚出来的」，
是就不追。

### 1.5 键盘与无障碍

- 每列是 `role="spinbutton"`，`↑↓` ±1、`Shift+↑↓` ±5、`PageUp/Down` ±5、`Home/End` 到两端；
- 列里的 60 个数字**不进 Tab 序列**（`tabIndex={-1}`）—— 逐个 Tab 过去是灾难，
  鼠标能点、键盘用列上的快捷键，两条路都通；
- 打开面板时焦点落在「时」列，`Esc` 收起并把焦点还给触发按钮；
- 没选日期时触发按钮**置灰**（`title="先选上面的日期"`），
  免得出现「我设了 9 点却不生效」这种困惑。

### 1.6 默认 22:30

用户当场改过一次：「说错了，是默认22点半」。
所以 `DEFAULT_DUE_TIME = '22:30'`，一打开就是 22:30。

## 二、今日预算：按日期存到云端

### 2.1 原来的样子

只存 `localStorage`，键是 `priorknow.budget-minutes`，**而且读不到就预填 180**。
两个后果：换设备就没了；「空状态提示」永远不可能出现（因为永远有值）。

### 2.2 现在

- **按日期存**：一天一条，隔天自然变空 → 那天重新填；
- **本机 + 云端双写**：先写本机（几乎不会失败），再推云端（可能失败）；
- **空状态主动问**：没填时给一块虚线面板 + 四个快捷值（1 / 2 / 3 / 4 小时）；
- **说清存到哪儿了**：输入框下面一行小字 —— 「已存到云端 · 换台设备也看得到」/
  「只存在这台设备 —— 在『数据与设置』里填了接口地址，就能跟着账号走」。

### 2.3 🔴 为什么是「一天一条」而不是「一个默认值」

这是当着用户面拍板的（给了三个选项，他选了「按日期存」）。理由：

「今日剩余时间」字面上就是逐日变化的 —— 今天只剩 3 小时、明天有 8 小时。
若只存一个默认值，用户每天都得改同一个数字，而且**「今天填过没有」无从判断**，
空状态提示也就永远只出现一次。

代价也认了：**每天都要填一次**。这是这个语义的自然结果，不是 bug。

### 2.4 两张表，不合并

预算是**设置**，不是任务。塞进 `tasks` 会有三个具体后果：

1. 「全部任务」页多出一条没有标题的怪行（或者到处都要 `WHERE kind != 'budget'`）；
2. 它会被卷进增量同步的 `seq` 体系 —— 而它根本不需要「谁先谁后」；
3. 回收站、墓碑、90 天清理这些生命周期对它毫无意义，但代码要逐个特判。

一张两列的表比这些副作用便宜得多。表结构与约束见
`docs/规格/api-contract.md` 第五节「第二张表」，建表脚本 `db/migrate-03-budget.sql`。

### 2.5 冲突规则只有一条

```
云端有值            → 以云端为准（它是跨设备的真相源）
云端没有、本机有    → 把本机值补推上去（多半是上次没同步成功）
云端读失败          → 用本机值，界面说一句，不弹窗、不阻塞
```

没有时间戳比较、没有「谁更新谁赢」——预算只是一天的**一个数字**，
为它做一套冲突合并算法不值得，而规则一多就会开始出「昨天填的今天冒出来」这种怪事。

### 2.6 其它几个小决定

| 决定 | 理由 |
| --- | --- |
| `on_date` 用 `date` 不用 `timestamptz` | 「今天」是本地日历日。存时间戳就要回答「按谁的时区算这一天」，而服务端 UTC、用户 +08:00，晚 8 点后差一天 |
| 日期由**客户端**算好再传 | 服务端自己取「今天」会在跨零点时错一天 |
| `minutes: null` 表示清空 | `0` 只能表达「今天一分钟都没有」，表达不了「还没填」 |
| 用 `POST` 不用 `PUT` | 与 `/api/tasks` 一致；而且这本来就是 upsert 语义 |
| 只留 30 天 | 免费版没有定时触发器 → 写入成功后顺手清（惰性清理） |
| 不再预填 180 | 预填一个假数字会把 180 悄悄写进用户账户，也让空状态提示永不出现 |

## 三、验证

### 3.1 本机（`day25-check.mjs`，31 项全过）

跑在 `vite preview` 的构建产物上，不靠「看起来不错」：

```
预算：空状态提示出现 / 输入框初始为空 / 4 个快捷按钮 / 点「3 小时」= 180
      本机缓存写入 {date, minutes} / 提示消失 / 出现「大约能完成 N 件」
      超 1440 明确说没保存且不覆盖旧值
时间：没选日期时禁用 / 默认 22:30 / 选日期后可用 / 面板展开 / 两列滚轮
      时列初始滚到 22 那格（792px = 22×36）
      mask-image 生效（读到 linear-gradient）
      scroll-snap-type = y mandatory
      选中框 top 72px / height 36px、选中项 22 加粗
      滚到半格 → 取整到 09、松手停在 324px（9×36）
      ↑ 小时 +1、End 跳到 23、点分钟「05」→ 00:05、完成收起面板
      调回 22:30 后提交 → dueAt = 2026-11-05T14:30:00.000Z（本地 22:30）
窄屏：390px、面板展开时无横向溢出
```

### 3.2 云端接口（curl，逐条）

| 请求 | 结果 |
| --- | --- |
| `GET ?date=…`（空） | `minutes: null` |
| `POST {minutes: 180}` | 200 + 180 |
| `GET` 回读 | 180 |
| `POST {minutes: 90}` 同一天 | 200 + 90（**upsert 生效**） |
| 另一个 `X-User-Id` 读同一天 | `null`（**分区隔离**） |
| `POST {minutes: null}` | 200 + null |
| 再 `GET` | null；`SELECT count(*)` = **0 行**（真的删了，不是写 0） |
| 缺 `X-User-Id` / 缺 `date` / `2026-02-31` / `5000` / `"60"` / 缺 `minutes` 键 / 请求体是数组 | 全部 400，各自一句人话 |
| `PUT /api/budget` | 405 |
| `OPTIONS` 预检 | 204 + `allow-methods: GET, POST, PATCH, DELETE, OPTIONS` |

### 3.3 公网端到端（`day25-e2e.mjs`，8 项全过）

localhost 不在 CORS 白名单，所以这条只能在线上验：过「风险提醒」中间页 →
配好接口地址与用户编号 → 填 120 → 界面显示「已存到云端」→
**直接问接口，云端确实有 120** → 清空 → 云端也清了 → 线上滚轮默认仍是 22:30、渐隐生效。
