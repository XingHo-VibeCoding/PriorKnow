**Day 14 的修复（本周唯一一处，且是同伴反馈驱动的）**

同伴第 2 条反馈：「**今日任务会显示所有任务，而且全部任务里面没有看到有独特的功能**」。

查证后确认这是**设计失误而非按 PRD 实现**：PRD 第五节原本规划的 3 个视图是
「今日队列 / 任务详情编辑 / 专注模式」，**根本没有「全部任务」** —— 是 Day 13 自己加的，
且与今日队列渲染同一个 `queue.ranked`，只是换了排版。

修法（只动2 个文件）：`TasksPage.tsx` 排序从优先级改成**按 `createdAt` 倒序**、
每行加行内「完成 / 删除 / 恢复为待办」、顶部加一句用途说明；`styles.css` 配套样式。

**修复的实测证据**（CDP 真点，非仅类型检查）：

| 验证项 | 结果 |
| --- | --- |
| 两个视图顺序是否真的不同 | ✅ 队列页首条 79.5 分那条；管理页首条 10.0 分（最后添加的）—— **集合相同、顺序完全不同** |
| 行内「完成」 | ✅ **直读 IndexedDB** 确认 `status: done`，分组变「待办 6 / 已完成 1」（总数 7 不变），提示条出现 |
| 行内「恢复为待办」 | ✅ 直读确认 `status: todo`，回到「待办 7 件」 |
| 375px 窄屏 | ✅ 两个视图各量到 7 件真实内容、零横向溢出 |
| 类型 / 打包 | ✅ `typecheck` 零错误；`build` 通过（CSS 16.73 → 17.09 kB，说明新样式真的生效） |

⚠️ **诚实记录一次返工**：窄屏复测第一轮量出「零溢出」，其实是**全新浏览器 profile 的
IndexedDB 是空的、页面根本没渲染内容** —— 量的是空气。加了「本页独有选择器存在」的守卫后
重测才是真结论。**这一轮踩的四个坑全是验证脚本的错，不是产品的错。**
