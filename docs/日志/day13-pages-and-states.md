# Day 13 页面路径与状态表

> 课程要求「**先列页面路径和状态表，再逐页实现**」。这份就是那张表 ——
> 在写任何代码之前先定清楚两件事：**每个视图承担什么任务**、**四种状态分别长什么样**。
> 顺序不能反：先写成功画面再补状态，结果一定是「四种状态里三种没见过」。

---

## 一、视图结构：3 个视图 + 1 个兜底页

课程原话是「**多页面不等于复制三张相似页面，而是每个页面承担不同任务**」。
所以三个视图不是把同一份内容切三段，而是回答三个不同的问题：

| 视图 | 用户此刻的问题 | 性质 |
| --- | --- | --- |
| 今日队列 | 「我**现在**该做哪一件？」 | 做决策 |
| 全部任务 | 「我手上总共有哪些事、哪些已经做完？」 | 做管理 |
| 任务详情 | 「这一件**凭什么**排这儿？我该怎么动它？」 | 追问原因 |

第三个视图尤其重要：本项目的主卖点是「**可解释的**自动排序」（`research.md` 的结论），
而「解释」目前只藏在队列卡片展开后的三因子明细里。给它一个独立页面，
是把「为什么排这里」从附属信息升格成**可以单独访问、可以发给别人看**的内容。

---

## 二、页面路径表

| # | 路径 | 视图 | 怎么进去 | 路由参数 |
| --- | --- | --- | --- | --- |
| 1 | `/` | 今日队列 | 导航「今日队列」 | — |
| 2 | `/tasks` | 全部任务 | 导航「全部任务」 | — |
| 3 | `/tasks/:id` | 任务详情 | 在「全部任务」里点某一条 | `id` = 任务 id |
| 4 | `*`（任意未知路径） | 未找到 | 手输一个不存在的地址 | — |

**导航**：页面外壳顶部放一条导航（两个标签：今日队列 / 全部任务），当前所在的那个高亮。
详情页属于「全部任务」这一区，所以在详情页时「全部任务」标签保持高亮，
另在页内给一个「← 返回全部任务」。

**路由方式**：`react-router-dom`（v7）。只用最基础的几个件 ——
`BrowserRouter` / `Routes` / `Route` / `NavLink` / `useParams`。
课程明写「今日不做：**路由库的进阶用法（够用就好）**」，
所以 loader / 嵌套路由 / 数据 API 这些一律不碰。

## 三、各视图的区块

### `/` 今日队列（现有内容搬过来，行为不变）

| 区块 | 说明 |
| --- | --- |
| 今日预算条 | 今天做得完几件 |
| 加任务 | 标题 / 截止 / 星级 / 预计时长 |
| 今日队列 | 筛选条 + 卡片列表 + 展开三因子明细（Day 12 成果，**一行不改**） |

### `/tasks` 全部任务

| 区块 | 说明 |
| --- | --- |
| 加任务 | 复用同一个 `TaskComposer` 组件 |
| 待办（N 件） | 每条：标题 + 分数 + 星级 + 截止 + 「查看详情 →」 |
| 已完成（N 件） | 每条：标题 + 「查看详情 →」 |
| 数据与设置 | 导出 JSON / 导入 JSON / 载入示例数据（复用 `DataPanel`） |

### `/tasks/:id` 任务详情

| 区块 | 说明 |
| --- | --- |
| ← 返回全部任务 | 回 `/tasks` |
| 标题 + 总分 | 这一件现在的总分 |
| 三因子明细 | 紧迫度 / 重要度 / 省时度 **各占多少分**（复用队列里的 `FactorBreakdown`） |
| 完整排序理由 | 逐条列出（队列卡片里是「·」连成一行，这里分开列） |
| 元信息 | 星级 / 预计时长 / 截止时间 / 当前状态 |
| 操作 | 待办任务：完成 / 删除；已完成任务：恢复为待办 |

## 四、状态表（今天的主角）

四种状态，**同一套判据**（都来自 `useTaskQueue` 的 `loaded` / `error`），
但**在每个视图上渲染成适合各自语境的样子** —— 这是关键，三个视图共用一套逻辑，
文案却各自说人话。

| 状态 | 判据（源码变量） | `/` 今日队列 | `/tasks` 全部任务 | `/tasks/:id` 任务详情 |
| --- | --- | --- | --- | --- |
| **加载中** | `loaded === false` | 「正在读取…」+ 转圈<br>副文案：正在从这台设备的浏览器里读任务 | 同左 | 同左 |
| **错误** | `error !== ''` | 「队列没读出来」<br>+ 具体原因 + 「重试」 | 「任务列表没读出来」<br>+ 原因 + 「重试」 | 「这件任务没读出来」<br>+ 原因 + 「重试」 |
| **空** | `loaded && error === '' && 列表为空` | 两种子情况：<br>① 一件都没有 → 「队列是空的」+「载入示例数据」<br>② 全做完了 → 「待办清空了」+ 已完成清单 | 「一条任务都没有」<br>+「载入示例数据」 | **「找不到这件任务」**<br>+ 说明「它可能已被删除，或地址里的编号不对」+「回全部任务」 |
| **成功** | 有数据 | 卡片列表（筛选条 + 序号 + 分数 + 理由） | 待办组 + 已完成组 | 分数 + 三因子 + 理由 + 操作 |

**详情页的「空」是真的**：不是摆一个假空态，而是**手输一个不存在的 id**（如 `/tasks/abc`）
就必然走到那里。这比造一个空数据有说服力 —— 它是一条**可证伪**的路径。

## 五、四种状态怎么才能被**真的看见**

⚠️ 这是本项目踩过多次的坑：本地 IndexedDB 读一次只要几毫秒、几乎不会失败，
「加载中」和「错误」**平时根本不会出现**。状态写在那儿却没人见过，等于没做。
所以要用「数据层状态」开关把它们主动演出来（Day 8 建的，Day 11 扩到四种模式）：

| 状态 | 怎么演出来 |
| --- | --- |
| 加载中 | 开关切「**模拟慢速**」→ 加载态停留 2.6 秒 |
| 错误 | 开关切「**模拟读取失败**」→ 直接给错误态 |
| 空 | 开关回「正常」，库里本来就没有任务（**首次打开就是这样**） |
| 成功 | 点「**载入示例数据**」→ 7 件示例任务 |

### ⚠️ 因此今天要把这个开关**从「数据与设置」里提出来，挪到页面外壳**

现在这个开关埋在首页底部的「数据与设置」卡片里。分成三个视图之后，如果它还留在那儿，
就会出现一个尴尬局面：**要演示「加载中」得先跑到 `/tasks` 改开关，再切回 `/` 看效果** ——
而 `/tasks` 那一瞬间也在加载中，切来切去反而看不清。

它本来就**不是**数据管理的一部分，而是「让状态可见」的工具。所以：
新建一个 `DevStateSwitch` 组件，放在**导航下方、页脚之前**，
三个视图都在同一位置能看到、随时能切。
