## 一、一句话定位

**知先是一款以动态优先队列为核心的「下一个最优行动调度器」。**

它不是普通 Todo List —— 普通清单只负责「记下来」，知先负责回答那个更难的问题：**我现在最该做什么？**

---

## 二、项目背景与痛点

传统 Todo 工具擅长「记录」，但不擅长「决策」。当任务变多时，用户面对的不是「没记下来」，而是：

- 截止时间、重要度、预计耗时混在一起，**看不出该先做哪个**；
- 容易先做简单但不重要的事，**重要的事一拖再拖**；
- 今日剩余时间有限，**不知道该做哪几件才做得完**；
- 任务一变（截止改了、重要度调了），**顺序要手动重排，费时费力**；
- 排序工具往往是「黑盒」，**用户不知道为什么它排第一**，于是不信任。

知先要解决的核心问题是：

> **把一堆任务，变成一条动态调整、可解释、可执行的行动队列。**

## 三、目标用户

| 人群 | 典型痛点 |
| --- | --- |
| 期末周学生 | 多门作业、实验报告、考试复习同时压来，不知道先复习哪科 |
| 多任务工作者 | 需求、会议、文档、沟通任务交织，一天被切得很碎 |

**共性**：不是「没有工具」，而是「工具不能帮我决定」。

## 四、核心机制

### 4.1 任务建模

每个任务包含以下字段：

| 字段 | 说明 |
| --- | --- |
| 标题 | 任务内容 |
| 截止时间 | 什么时候必须交付 |
| 预计耗时 | 预计要花多久（分钟 / 小时） |
| 重要度 | 1–5 星 |
| 依赖任务 | 可选，做完前置才能开始 |
| 当前状态 | 待办 / 进行中 / 已完成 |

### 4.2 优先级计算

系统根据字段算出优先级分数：

```text
紧迫度 = 1 / max(剩余小时, 1)
优先级 = 重要度 × 2 + 紧迫度 × 3 − 预计耗时 × 0.1
```

> 首版使用这组权重；后续所有可调参数都集中在 `core/priority.ts` 一个文件里，方便按需调整或让用户自定义。

### 4.3 优先队列（数据结构）

用**二叉堆（优先队列）**维护任务顺序：

- 插入新任务 → **上浮**
- 完成任务 / 参数变化 → **下沉**
- 每次变化都伴随**重排动画**

这是本项目的技术核心，也是演示时最有记忆点的部分：**任务的排序过程是看得见的**。

### 4.4 可解释排序（最重要）

**排序不是黑盒。** 每个任务都能看到「为什么它排第一」，例如：

> 「明天截止 + 重要度 5 星 + 只需 1 小时 → 排第 1，建议现在做。」

可解释性分两层：

1. **文字层**：显示优先级分数 + 排序原因
2. **可视层**：分数由哪几项构成，逐项动画展示（详见 5.4）

## 五、核心功能

### 5.1 自然语言快速添加

输入：「明天下午交实验报告，大概 2 小时，很重要。」

自动解析出：标题 / 截止时间 / 预计耗时 / 重要度。

- **首版**：本地规则解析（正则 + 关键词表），不依赖任何外部服务
- **后续**：可选接入 AI 增强解析（仅在有余力时，且必须避免密钥泄露与按量计费）

### 5.2 优先队列可视化

用**堆树 / 跑道 / 瀑布流**等形态展示任务顺序。任务完成或参数变化时，有上浮、下沉、重排动画。

> 这是比赛演示的记忆点：**别人展示列表，我们展示队列在动。**

### 5.3 自动优先级与可解释排序

显示优先级分数和排序原因，让用户信任系统，而不是手动拖拽。

### 5.4 极致可解释可视化（本项目亮点）

在 5.3 基础上再进一步，把「计算过程」变成可交互、可玩的：

- **拖动滑块**调整截止时间 / 重要度 / 耗时 → 队列**实时重排**
- 优先级公式做成「白板」，每个变量拖一下，卡片跟着动
- 「为什么排第一」以**动画过程**呈现：先看紧迫度，再看重要度，最后扣耗时

> 这一步把产品从「有个排序算法」升级成「让算法透明、可信、可玩」。

### 5.5 决策模拟（本项目亮点）

让用户能预演「如果……会怎样」：

- **跳过模拟**：「如果这个任务今天不做，明天的队列会怎样？」
- **状态降级**：输入「今天状态不好」→ 自动降低今日任务量、优先推短平快任务
- **习惯洞察**：「我最常推迟的是什么类型的任务？」（基于本地统计，不上云）

### 5.6 今日时间预算

输入「今天还剩 3 小时」，系统自动选出**不超过预算**的一组任务，并按优先级生成今日行动队列。

> 这是从「全量任务」到「今天能做完什么」的关键一步。

### 5.7 专注模式

只显示队首任务，倒计时执行。完成后，下一个任务自动浮上来。

> 这是从「计划」到「执行」的闭环。

### 5.8 本地优先，无云依赖

- 数据存储在浏览器 **IndexedDB**（通过 Dexie.js）
- 支持**导出 / 导入 JSON**，随时备份
- **PWA 离线可用**，断网也能打开和操作
- 不需要云服务器，可部署在任意免费静态托管（Vercel / Netlify / GitHub Pages）

### 5.9 分享卡片（本项目亮点）

完成今日队列后，自动生成一张**今日完成情况卡片**（可截图分享）。分享机制不依赖社交账号、不上传数据，纯粹由用户主动导出。

### 5.10 示例数据与引导

内置「期末周冲刺」示例数据，让评委和用户 **30 秒内理解产品价值**。

## 七、技术方案

### 7.1 技术栈

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 构建 | **Vite** | 启动快，生态成熟 |
| 框架 | **React + TypeScript** | 类型安全，零基础也能靠 AI 辅助上手 |
| 样式 | **Tailwind CSS** | 原子类，改样式快 |
| 动效 | **Framer Motion**（或 CSS 动画） | 队列上浮、下沉、重排动画 |
| 状态 | **Zustand** 或 Context + useReducer | 轻量，不引入大依赖 |
| 存储 | **Dexie.js / IndexedDB** | 本地优先，离线可用 |
| 测试 | **Vitest** | 重点测核心算法 |
| PWA | **vite-plugin-pwa** | 可安装 + 离线 |
| 部署 | 免费静态托管 | 不买域名、不租服务器 |

### 7.2 核心算法独立成纯 TypeScript 模块

```text
core/
  priorityQueue.ts   // 优先队列 / 二叉堆（上浮、下沉）
  priority.ts        // 优先级公式（权重集中在这里）
  scheduler.ts       // 今日时间预算（背包式筛选）
  parser.ts          // 自然语言解析（本地规则版）
  types.ts           // 类型定义
```

**关键约束：`core/` 不依赖 React。**

这带来两个好处：

1. 算法可以**独立测试**（Vitest 直接测纯函数）
2. 未来转微信小程序或 App 时，**UI 重写，核心算法直接复用**

### 7.3 数据流

```text
用户输入
  → parser（解析成结构化任务）
  → IndexedDB（持久化）
  → priority（算分）
  → priorityQueue（排成队列）
  → UI 渲染 + 动画
  → 用户完成/修改 → 重新算分 → 队列重排 → 回到 UI
```

### 7.4 关于云端（可选、最小化）

本项目**以本地为唯一真实数据源**。云端仅作为可选的非核心补充，例如：

- 跨设备同步用户偏好（「今天剩 3 小时」这类设置）
- （选做）AI 解析增强

**约束**：不开付费套餐、不用按量计费、不配通配符 CORS、不提交任何密钥。

- 解析器若规则覆盖不全：保证最常用的几种句式（时间 + 时长 + 重要度）
