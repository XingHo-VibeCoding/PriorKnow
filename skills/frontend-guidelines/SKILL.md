## 页面层级

- 每个页面只有一个主标题
- 区块之间靠间距分组，不靠加边框
- 区块标题要比它管的内容明显大（≥18px），正文 14px

## 颜色与字体

- 正文 14px；标签 / 元信息 13px 为下限；**11px、12px 全部消灭**
- 正文与背景的对比度 ≥ 4.5:1；非文字 UI 元素（图标、边框、焦点环）≥ 3:1
- 浅灰字不要放在白底上
- 算对比度要用「叠加后的有效色」：文字最终色 = 透明度 × 文字色 + (1 − 透明度) × 页面底色。
  底色取 `body` 的实色，**不要取中间层**（它可能是透明的，会被当成黑色，算出离谱值）
- 对比度必须用脚本算，不能目测：`#8e8b95` 只有 3.35:1（不合格），肉眼几乎看不出

## 卡片与按钮

- 卡片内边距 16px（窄屏 13px），卡片间距 12px
- 按钮要有默认、悬停、禁用三种状态
- 给卡片做状态强调时，用 `inset box-shadow` 画竖条或边框，**不要改 background** ——
  换底色会重新压低卡片内小字的对比度
- 图标用内联 SVG，不要用 `✓` 这类字符（微软雅黑缺字形，会渲染成方框）

## 移动端

- 360px 与 375px 宽度下都不能出现横向滚动：断言 `scrollWidth === clientWidth`
- 「断点两侧行为相反」的规则是最好的宽度指纹（如按钮竖排 / 横排），比量像素可靠

## 修改前

- 先列出具体问题，再逐个修复，一次只改一个
- 全部用实测值（`getComputedStyle`），**不要读 CSS 源码** —— 源码写了不等于生效
- 分清「真问题」和「期望值写错了」：断言失败时先问是产品错了还是自己的期望错了

## 修改后

- 桌面宽度和手机宽度各看一遍
- 确认交互没有因为改样式而失效（点星、加任务、展开明细、删除都要真点一遍）
- 焦点可见性要**真发 Tab 键测**，不能扫 CSS 有没有 `:focus` ——
  浏览器对 `<button>` 自带默认焦点环，扫 CSS 得出的「缺焦点样式」多半是假问题
- `npm run build` 必须通过
